## 对话与关键决定

- **架构选浏览器内推理**（ONNX Runtime Web）：本机版 / 云端版共用、图片不离开电脑、无需服务端依赖。否决了服务端 Python 推理（需要 pip）、第三方 API（上传 + 密钥 + 费用）、传统算法（效果差）。
- **模型选 BiRefNet_lite 512 fp16（MIT）**：8 张测试照片上质量最稳，单线程 WASM 约 9 s。U²-Netp 太差；ISNet 白色主体会变半透明，且 onnx-community 版标 AGPL；RMBG-1.4 质量好但 BRIA 许可不允许商用；1024 版 BiRefNet 在浏览器内内存不足。比较细节见 [experiments/smart-cutout-2026-11-17](../experiments/smart-cutout-2026-11-17/README.md)。
- **组件不进仓库**：运行库与模型共约 121 MB，按 `js/cutout-manifest.js` 固定版本 + 大小 + SHA-256 + 多个镜像地址在首次使用时下载（先征得同意），存在浏览器独立的 IndexedDB 库，之后离线可用。
- **云端版由服务器镜像组件**：不放宽 CSP 到外部 CDN，而是服务器启动后后台下载到数据卷 `vendor/cutout/` 再同源提供；CSP 只加 `'wasm-unsafe-eval'`；加 COOP / COEP 启用多线程（6–7 s / 张）。`CC_CUTOUT=0` 可关闭，`admin cutout` 手动检查 / 下载，离线服务器可手动放入文件。
- **蒙版放大**：试过导向滤波，在发丝和白鞋边出现光晕，改为高质量缩放 + 按放大倍数收紧过渡带。
- **WebGPU 只在适配器支持 `shader-f16` 时启用**（fp16 模型要求），否则 WASM；显卡出错时 Worker 自动改用 WASM 重算，窗口里也可手动「改用处理器重算」（记在 localStorage）。
- **结果保存方式**：照片存 WebP、图形存 PNG；默认裁掉透明边且主体不移位；`layer.cutout = { src, rect }` 记录原图，支持「恢复原图」（旋转 / 翻转 / 缩放后仍准确）和「保留原图层」。原图计入已用资源，不被打开工程时的清理删除，另存 `.chaos` 时一并打包。
- 测试照片来自 Pexels，含这些照片的截图不提交（延续此前清理第三方图片的做法）。
